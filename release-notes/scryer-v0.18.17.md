# scryer-v0.18.17

AI generated release notes

## What's Changed

- Torrent seed criteria now live on **seeding profiles**. A profile carries a ratio goal, a seed-time goal, an optional season-pack override, whether tracker minimums are honored, what happens once the goal is met (remove the entry, stop seeding, or keep it), a never-remove switch, a minimum-seeders threshold, and whether Scryer keeps managing the torrent after import. Assign a profile to an indexer, to a download-client routing entry, or as the global default in Settings > Indexers > Seeding Profiles. If you are coming from Sonarr this is the familiar shape: the resolved ratio and seed time are pushed to the download client when the torrent is added, and the goals a torrent was grabbed under are frozen with the grab, so editing or deleting a profile later never changes a torrent that is already running.
- When more than one level could apply, the indexer that supplied the release wins, then seed criteria imported from Prowlarr for a managed child, then the download-client routing entry, then the global default. The first profile that answers wins as a whole, so assigning a profile to an indexer is how you override everything below it.
- **Nothing is removed just because it finished importing.** Every torrent passes one removal gate, whether or not you use profiles. With no profile, Scryer removes an entry only when the download client itself reports the seeding obligation discharged, and holds it when the client cannot answer. With a profile, Scryer's own goal is authoritative in both directions: a client's "this can be removed" no longer releases an unmet goal, and its "this cannot be removed" no longer vetoes a met one. Either the ratio or the seed-time goal being reached discharges the obligation.
- **Private trackers get a hard rail.** A torrent the client reports as private is never auto-removed on the client's word alone — only a goal Scryer can prove was met, or your own action, releases it. A client that does not report the private flag leaves it *unknown*, and unknown is never read as public. Set `never remove` on the profile to seed forever, or `hand off` to give the torrent back to your client's own limits: the entry is left exactly as it is, is never auto-removed, and leaves Scryer's queue. Blackhole torrents are never auto-removed at all, because their removal is a delete of a watch folder something else is seeding from.
- **Minimum seeders.** A seeding profile can require a minimum seeder count before a release is grabbed. Leave it blank to use the new *Default minimum seeders* setting (1 by default), enter `0` to turn the check off entirely, or enter a number to require it. The check runs on automatic and RSS grabs, on download-token redemption, and on delayed releases when they are promoted; interactive search shows the release with Queue disabled and the reason on the row. Releases whose indexer reports no seeder count are always allowed through, and your own force-grab always bypasses the check.
- **A download client's warning is no longer treated as a failed download.** Recoverable client conditions — qBittorrent's `error` and `missingFiles`, Transmission's error string and the equivalents on other clients — now show as their own `Warning` state in Activity, carrying the client's message, with a matching filter chip. They are no longer blocklisted, removed and re-searched as failures. Unrecognized client states are treated as still downloading instead of as warnings or errors.
- Prowlarr-managed torrent indexers import their seed criteria more completely: ratio, seed time and season-pack goals as before, plus the minimum seeders Prowlarr itself would push (`appMinimumSeeders`, falling back to the app profile's value). Assigning a Scryer seeding profile to a managed indexer overrides everything Prowlarr holds for it.

## Upgrade Notes

- **Update your torrent download-client plugins before or with this release.** Scryer now checks the removal and file-move verdicts it gets from a download-client plugin against the plugin version that first reported them honestly. Torrents on an older plugin are held rather than removed, and a held torrent's import hardlinks or copies rather than moving files, until the plugin is updated in Settings > Plugins.
- **Goal-met and failed removals now delete the download client's copy of the data**, matching Sonarr's behavior. When the gate releases a torrent after a verified import, the entry and the client's payload go together; a failed torrent's cleanup deletes data only when the client says the item can be removed. Files already hardlinked into your library are unaffected, a copy-mode import simply frees the duplicate, and Scryer never asks a blackhole watch folder, an ignored download, or a usenet client to delete anything. If you cross-seed the same payload from a second torrent, this is the same caveat it is in Sonarr.
- **Prowlarr-managed torrent indexers now always carry a minimum-seeders value.** Prowlarr's app profile ships a minimum of 1 by default, and Scryer applies Prowlarr's own rule, so those indexers resolve at the Prowlarr tier and no longer inherit a raised *Default minimum seeders* or the global default profile's minimum. If you raised the Scryer floor and rely on Prowlarr-managed indexers, either raise the value in Prowlarr's app profile or assign a Scryer seeding profile to the indexer. A Prowlarr child that supplies only goals now inherits the global default profile's minimum, including an explicit `0`.
- **A warned download no longer raises a failure notification.** This is the point of the new `Warning` state, but if you relied on that notification to hear about a stuck torrent, watch the Activity page's attention items instead.
- Delayed (pending) releases now record the seeder count they were parked with and are re-judged against the current threshold when they are promoted automatically, so raising the floor while a release is parked takes effect. Releases parked by an earlier version have no recorded count, so they are treated as unknown and allowed through. Reacquisition after a failed download is an automatic grab and is judged the same way.

## Other Improvements

- The indexer table's seeding-profile picker now names the minimum seeders a Prowlarr-managed indexer imported ("Inherit default · Prowlarr minimum N seeders", or "seeder check off" for 0), so the value that governs admission is visible where it is chosen.
- The seeding-profile list now calls out a minimum that deviates from the default — "seeders check off" for an explicit `0`, or the threshold itself — alongside the existing hand-off, never-remove, season-pack and tracker-minimum markers.
- Seed-time fields accept durations such as `90m`, `36h`, `1d 12h` or `2w`; a plain number is still minutes.
- The minimum-seeders field explains that a profile assigned only through a download-client routing entry does not apply its minimum (the check runs before a client is chosen), and that leaving it blank inherits the *Default minimum seeders* setting rather than a Prowlarr-imported value.
- Torrent queue rows carry their seeding state, observed ratio and seed time alongside the goals they are being measured against.
