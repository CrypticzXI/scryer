# scryer-v0.18.17

AI generated release notes

## What's Changed

- Torrent seed criteria now live on **seeding profiles**. A profile carries a ratio goal, a seed-time goal, an optional season-pack override, whether tracker minimums are honored, what happens once the goal is met (remove the entry, stop seeding, or keep it), a never-remove switch, a minimum-seeders threshold, and whether Scryer keeps managing the torrent after import. Assign a profile to an indexer, to a download-client routing entry, or as the global default in Settings > Indexers > Seeding Profiles. If you are coming from Sonarr this is the familiar shape: the resolved ratio and seed time are pushed to the download client when the torrent is added, and the goals a torrent was grabbed under are frozen with the grab, so editing or deleting a profile later never changes a torrent that is already running.
- When more than one level could apply, the indexer that supplied the release wins, then seed criteria imported from Prowlarr for a managed child, then the download-client routing entry, then the global default. The first profile that answers wins as a whole, so assigning a profile to an indexer is how you override everything below it.
- **Nothing is removed just because it finished importing.** Every torrent passes one removal gate, whether or not you use profiles. With no profile, Scryer removes an entry only when the download client itself reports the seeding obligation discharged, and holds it when the client cannot answer. With a profile, Scryer's own goal is authoritative in both directions: a client's "this can be removed" no longer releases an unmet goal, and its "this cannot be removed" no longer vetoes a met one. Either the ratio or the seed-time goal being reached discharges the obligation.
- **Private trackers get a hard rail.** A torrent the client reports as private is never auto-removed on the client's word alone — only a goal Scryer can prove was met, or your own action, releases it. A client that does not report the private flag leaves it *unknown*, and unknown is never read as public. Set `never remove` on the profile to seed forever, or `hand off` to give the torrent back to your client's own limits: the entry is left exactly as it is, is never auto-removed, and leaves Scryer's queue. Blackhole torrents are never auto-removed at all, because their removal is a delete of a watch folder something else is seeding from.
- **Minimum seeders.** A seeding profile can require a minimum seeder count before a release is grabbed. Leave it blank to use the new *Default minimum seeders* setting (1 by default), enter `0` to turn the check off entirely, or enter a number to require it. The check runs on automatic and RSS grabs, on download-token redemption, and on delayed releases when they are promoted; interactive search shows the release with Queue disabled and the reason on the row. Releases whose indexer reports no seeder count are always allowed through, and your own force-grab always bypasses the check.
- **A download client's warning is no longer treated as a failed download.** Recoverable client conditions — qBittorrent's `error` and `missingFiles`, Transmission's error string and the equivalents on other clients — now show as their own `Warning` state in Activity, carrying the client's message, with a matching filter chip. They are no longer blocklisted, removed and re-searched as failures. Unrecognized client states are treated as still downloading instead of as warnings or errors.
- Prowlarr-managed torrent indexers import their seed criteria more completely: ratio, seed time and season-pack goals as before, plus the minimum seeders Prowlarr itself would push (`appMinimumSeeders`, falling back to the app profile's value). Assigning a Scryer seeding profile to a managed indexer overrides everything Prowlarr holds for it.
- **Indexer convergence now re-opens per failing indexer.** A release that is grabbed and then fails — the download client fails it, or an import gate rejects it — no longer leaves that scope "converged" for the indexer it came from. Scryer drops only that indexer's coverage row, the blocklist excludes the burned release, and the next convergence pass re-queries just that indexer for the next-best release, repeating until an import succeeds or the indexer has nothing left. Operator triggers (*Search*, queue replacement, *Search monitored*, mismatch recovery) re-query every routed indexer again. The blocklist entry is written before the scope is re-opened, so a woken cursor can never re-grab the release that just failed.
- **Import-gate rejections are now failed downloads.** When a gate burns a release — missing required audio language, an invalid or sample file, an implausible runtime, a post-download rule, implausible episode coverage — the download is marked *Failed* with the rejection as its message instead of parking as *Import blocked*, the Wanted scope is searched again right away, and the item is removed from the download client when that client's *Remove failed* toggle is on (Sonarr's failed-download handling). Rejections that need a decision from you — unresolved identity, route mismatch, "existing file is equal or better", already imported, path problems — still park as *Import blocked*.

### Acquisition: one scoring path for grab, import and upgrade

- **Quality tier is compared before score, and scores are re-baselined.** The tier no longer adds points, so every score is on a new scale and ordinary releases can score negative. A better tier always wins; score decides within a tier. Release age and season-pack coverage no longer change a score — they only order search results.
- **PROPER and REPACK releases are understood.** A re-release of the quality you already have is compared on its revision before its score: a PROPER that fixes a broken encode is fetched even when it scores slightly lower, and the original is never fetched over a PROPER already on disk. A scope at its quality cutoff can still pick up a PROPER from an RSS feed; active search does not hunt them, and a PROPER is never fetched off a feed for a file imported more than a week ago, whether or not the scope has reached its cutoff. The repack rule only applies where it means something: a REPACK filling a missing episode, or of a better quality, is no longer refused because its release group is unknown or different.
- **Downloads already in the queue are compared like files on disk.** A better release can be grabbed over a slow or stuck one; an equal or worse one is refused with a reason that says so (`queued_better_or_equal`); a download stuck at "import blocked" no longer makes its scope permanently unsearchable; a profile that forbids upgrades does not fetch an upgrade beside a download already in flight (a PROPER still is). A failed download awaiting its failure handler, and a client whose queue cannot be listed, still pause the scope.
- **Quality profiles gained a separate cutoff score** (`cutoffScore` over the API; a web control follows). It stops same-tier upgrades once a file is good enough and leaves the minimum score to its original job — refusing releases that score too low to grab at all.
- **Season packs and multi-episode batches are judged per member at grab time:** a pack or batch is fetched when a monitored episode it covers is missing or improvable — a batch that fills four missing episodes is fetched even when the fifth already holds a better file — and refused while any covered episode has not aired (24 h grace) or is not monitored. Each landed file is then gated on its own at import. A season counts as "at cutoff" only when every monitored episode is.
- **Import decisions run through one gate** for episodes, movies, series-owned movies and pack members, and import accepts an equal score (rejects only downgrades) without enforcing "allow upgrades" — that is grab-side policy, as in Sonarr. A refused import says what it costs the release: a proven lie (the file measures a lower resolution than advertised, or contradicts a stated codec with one the profile blocks) is blocklisted and the scope re-searched; a release that merely lost the comparison is skipped; anything that needs a human is held. Nothing is blocklisted for not being an upgrade, and a file the profile vetoes over something the release name never disclosed (HDR, Dolby Vision, a codec on a silent name, a custom file rule) is held for review instead of blocklisted. Operator-chosen imports are never overruled.
- **Release size scores on a smooth curve instead of steps**, so a file that lands a few percent under the advertised size no longer drops a whole bracket — the cause of "grabbed, then refused as a downgrade at import". A release far smaller than its quality and runtime imply is refused at grab (specials exempt; the floor sits at or below Sonarr's per-quality minimum). Episodes are scored against their own length at grab, at import and when the library file is re-scored.
- **Delayed releases are re-scored and re-ordered when their timer expires**, against the profile as it stands now, and a season pack parked by a delay profile faces the same pack rules as any other pack.
- **Interactive search lists the best quality first** (tier, then PROPER/REPACK, then score); torrents with more seeders are preferred after indexer priority. The Wanted page shows the live current score — the same re-derived number every decision compares against — including scopes that were never searched and multi-episode files.
- Fixed: the import truth check compared the file against itself, so a release that landed at a worse quality than it advertised was never caught; a refused movie import could add a second primary file to a title; importing an upgrade for a series-owned movie could crash when the replaced file had a different filename; a manually chosen file for a movie or series-owned movie could be refused and blocklisted; a search whose title failed to load reported "no results" and marked the scope searched; custom rules reading the file's video codec saw different values at import and afterwards; the movie scan's primary-file choice ignored quality tier; rejected series-owned-movie and season-pack imports did not re-open the right scope, and a season pack wrote one blocklist row per file instead of one per release.

## Upgrade Notes

- **Update your torrent download-client plugins before or with this release.** Scryer now checks the removal and file-move verdicts it gets from a download-client plugin against the plugin version that first reported them honestly. Torrents on an older plugin are held rather than removed, and a held torrent's import hardlinks or copies rather than moving files, until the plugin is updated in Settings > Plugins.
- **Goal-met and failed removals now delete the download client's copy of the data**, matching Sonarr's behavior. When the gate releases a torrent after a verified import, the entry and the client's payload go together; a failed torrent's cleanup deletes data only when the client says the item can be removed. Files already hardlinked into your library are unaffected, a copy-mode import simply frees the duplicate, and Scryer never asks a blackhole watch folder, an ignored download, or a usenet client to delete anything. If you cross-seed the same payload from a second torrent, this is the same caveat it is in Sonarr.
- **Prowlarr-managed torrent indexers now always carry a minimum-seeders value.** Prowlarr's app profile ships a minimum of 1 by default, and Scryer applies Prowlarr's own rule, so those indexers resolve at the Prowlarr tier and no longer inherit a raised *Default minimum seeders* or the global default profile's minimum. If you raised the Scryer floor and rely on Prowlarr-managed indexers, either raise the value in Prowlarr's app profile or assign a Scryer seeding profile to the indexer. A Prowlarr child that supplies only goals now inherits the global default profile's minimum, including an explicit `0`.
- **A warned download no longer raises a failure notification.** This is the point of the new `Warning` state, but if you relied on that notification to hear about a stuck torrent, watch the Activity page's attention items instead.
- Delayed (pending) releases now record the seeder count they were parked with and are re-judged against the current threshold when they are promoted automatically, so raising the floor while a release is parked takes effect. Releases parked by an earlier version have no recorded count, so they are treated as unknown and allowed through. Reacquisition after a failed download is an automatic grab and is judged the same way.
- **"Remove failed" now defaults to on** for new and unset download-client routing entries, matching Sonarr. Entries you already have keep their saved value — including a `false` that an earlier startup normalization wrote — so if you want burned imports removed on an existing install, turn *Remove failed* on under that client's routing settings.
- **Burned usenet imports delete the client's copy of the data.** Scryer removes the job's output folder itself — never a library root, title folder, recycle bin, or a remote-path-mapping root, and a file sitting directly in a shared category folder is deleted on its own — and asks SABnzbd (`del_files=1`) and Weaver (`deleteFiles`) to drop what they hold; NZBGet has no such flag, so Scryer's own removal covers it. A burned torrent is never removed until the seeding gate releases it — the same hold, private-tracker rail, never-remove and hand-off rules as an imported torrent — and then entry and data go together when *Remove failed* is on.

- **Scores are re-baselined** (quality tier no longer adds points). Quality profiles' "minimum score to grab" values are reset to unset — old values were calibrated against the tier-inclusive scale and would silently block every release. Set a new value against the new scale if you want a floor.
- The *cross-tier minimum delta* acquisition setting no longer does anything: tier is compared before score, so no delta ever sees a cross-tier comparison. The GraphQL field is deprecated and the control is hidden; the stored value is ignored and will be removed in a later minor.
- A download stuck at "import blocked" no longer freezes its scope: a better release may be grabbed beside it; an equal or worse one is refused.
- Database: `wanted_items.current_score` is dropped (the current score is always re-derived), `min_score_to_grab` is removed from stored scoring configs, and `download_submissions.release_size_bytes` is added (nullable; downloads queued before the upgrade compare without a size).

## Other Improvements

- The indexer table's seeding-profile picker now names the minimum seeders a Prowlarr-managed indexer imported ("Inherit default · Prowlarr minimum N seeders", or "seeder check off" for 0), so the value that governs admission is visible where it is chosen.
- The seeding-profile list now calls out a minimum that deviates from the default — "seeders check off" for an explicit `0`, or the threshold itself — alongside the existing hand-off, never-remove, season-pack and tracker-minimum markers.
- Seed-time fields accept durations such as `90m`, `36h`, `1d 12h` or `2w`; a plain number is still minutes.
- The minimum-seeders field explains that a profile assigned only through a download-client routing entry does not apply its minimum (the check runs before a client is chosen), and that leaving it blank inherits the *Default minimum seeders* setting rather than a Prowlarr-imported value.
- Torrent queue rows carry their seeding state, observed ratio and seed time alongside the goals they are being measured against.
