# Scryer 0.18.17 release notes

These notes describe the net change from `scryer-v0.18.16` to `scryer-v0.18.17`. Intermediate release-branch behavior is omitted.

## What's Changed

### Dashboard, catalog, and accounts

- **A new Dashboard brings the operational picture together.** It shows library totals, recent grabs, upgrades, imports and failures, requests awaiting action, manual-import work, recently imported titles, indexer health and quota state, storage usage, and available plugin updates with links to the full views.
- Title overviews now include a top-billed cast rail backed by a local credits cache. Catalog rows and cards show when a title has download work in progress, and adding a title from global search leaves the search panel open for another addition.
- **Administrators now issue temporary passwords instead of permanent replacements.** The user must choose a new password after local sign-in, and resetting another user's password revokes that user's active sessions. Password-based sign-ins now finish with an enrolled passkey or authenticator/recovery code when the account has one, rather than treating an enrolled factor as optional.

### Plugins

- **Official plugin patch updates can be applied automatically.** Enable the option in Settings > Plugins to install the compatible patch—or a same-version optimized artifact—selected by the scheduled signed-catalog refresh. Each update uses the normal install validation and rollback path, failures leave the refresh job in a warning state, and update badges appear in Settings and on the Dashboard.
- Indexer plugins can now use the command ABI while legacy Extism indexers remain supported. The bundled Newznab and Torznab indexers are updated to 2.0.1.

### Seeding profiles and download state

- Torrent seed criteria now live on **seeding profiles**. A profile carries a ratio goal, a seed-time goal, an optional season-pack override, whether tracker minimums are honored, what happens once the goal is met (remove the entry, stop seeding, or keep it), a never-remove switch, a minimum-seeders threshold, and whether Scryer keeps managing the torrent after import. Assign a profile to an indexer, to a download-client routing entry, or as the global default in Settings > Indexers > Seeding Profiles. Resolved goals are pushed to the download client when the torrent is added and frozen with the grab, so later profile edits do not rewrite a running torrent's obligation.
- Seed goals and seeder admission are resolved independently. Goals follow the assigned indexer profile, Prowlarr's imported goals, the download-client routing profile, then the global profile. Minimum seeders is resolved before a client is chosen, from the assigned indexer profile, Prowlarr's imported minimum, then the global profile/default floor. An assigned Scryer profile answers as a unit—a blank minimum inherits the floor—while Prowlarr contributes only the individual fields it actually owns.
- **Nothing is removed just because it finished importing.** Every torrent passes one removal gate. Without a profile, removal requires the download client to report that its seeding obligation is discharged. With a profile, Scryer's frozen goal is authoritative in both directions: the client cannot release an unmet goal or veto a met one. Either the ratio or seed-time goal being reached discharges the obligation.
- **Private trackers get a hard rail.** A torrent reported as private is never auto-removed on the client's word alone; only a goal Scryer can prove was met, or an operator action, releases it. An unknown private flag is never read as public. `never remove` seeds forever, while `hand off` leaves the torrent and payload with the client and removes it from Scryer's queue. Blackhole torrents are never auto-removed.
- **Minimum seeders can gate torrent grabs.** Leave the profile value blank to use the *Default minimum seeders* setting (1 by default), enter `0` to turn the check off, or set a threshold. The check covers automatic, RSS, download-token, standby, and delayed-promotion grabs. Interactive search explains why Queue is unavailable; unknown seeder counts remain eligible, and force-grab bypasses the threshold.
- **Recoverable client conditions now have a distinct `Warning` state** in Activity, with the client's message and a matching filter. Warned downloads block duplicate grabs and can remain visible after import. A warning that persists for 24 hours becomes a failure for usenet and for torrents without resolved seed goals; profiled torrents remain under their seeding gate instead of timing out as failed.
- Prowlarr-managed torrent indexers import ratio, seed time, season-pack time, and the minimum seeders Prowlarr would apply (`appMinimumSeeders`, falling back to its app profile). Assigning a Scryer profile to the indexer overrides Prowlarr at that tier.

### Acquisition: one scoring and recovery path

- **Quality tier is compared before score, and scores are re-baselined.** Tier points are excluded from the score, so ordinary releases can score negative. A better tier always wins; score decides within a tier. Release age and season-pack coverage order results without changing the score.
- **PROPER and REPACK releases are understood.** A same-quality re-release is compared on revision before score. RSS can pick up a PROPER at cutoff, subject to the one-week file-age guard, while active search does not hunt same-tier PROPERs. A REPACK that fills missing episodes or improves quality is eligible even when its release group differs.
- **Downloads already in the queue are compared like files on disk.** A better release can be grabbed over a slow or stuck one; an equal or worse release is refused with `queued_better_or_equal`. An import-blocked item does not freeze its scope, while a failed item awaiting handling or a client whose queue cannot be listed still pauses it.
- **Quality profiles gained a separate cutoff score** (`cutoffScore` over the API). It stops same-tier upgrades once a file is good enough while the minimum score remains the floor for grabbing a release at all.
- **Season packs and multi-episode batches are judged per member.** A pack is eligible when it fills or improves a monitored member, even if another covered episode already has a better file, and is refused while a covered episode is unmonitored or has not aired beyond the 24-hour grace. Each landed file is gated separately, and a season reaches cutoff only when every monitored episode does.
- **Automatic searches now retain their remaining ranked results as a standby list.** When a client failure or burned import re-opens a scope, Scryer blocklists the failed release and tries the next saved candidate without querying the indexer again. Single-episode candidates are tried before packs; failed packs retain runner-up packs for every covered episode. Once saved candidates are exhausted, the scope stays converged until an operator-triggered search refreshes it. Wanted now exposes this standby state.
- A stale 404/410 download link expires from standby without burning the release, while 401/403 responses defer with a credential error. A delayed standby winner remains parked instead of allowing a worse candidate behind it, and is re-scored, re-ordered, swarm-checked, and re-parked if necessary against the current profile when promoted.
- **Import decisions run through one gate** for episodes, movies, series-owned movies, and pack members. Equal scores are accepted and upgrade permission remains a grab-side rule. Objective automatic-import rejections—probe vetoes, required-audio, coverage/runtime, file-rule, or release-truth failures—mark the download failed, blocklist it, and advance to standby. Releases explicitly queued by an operator are instead held for manual import without blocklisting or removal. Identity, route, path, already-imported, and similar decisions that need an operator remain *Import blocked*.
- Grab and import now use the same size basis. When a landed file is at least 85% of its announced size, both passes score the announced size so container overhead does not manufacture a downgrade; a real shortfall still scores the landed file. The announced basis is retained with the media file so later re-scoring reproduces the import decision.
- Interactive search orders quality tier, PROPER/REPACK revision, then score; torrent seeder count breaks ties after indexer priority. An operator's manual Queue action remains available regardless of how negative the score is. Empty automatic searches complete normally, while a selected release that cannot be submitted because its mapped client is disabled reports the job as failed without blocklisting the release.

### Libraries, renaming, and filesystem handling

- Libraries can override metadata language and, for episodic libraries, season-folder behavior. Titles can override or inherit both values, including through bulk title editing, and imports, scans, refreshes, and rename previews use the resolved setting consistently.
- **Single-title and bulk renames now run as background jobs.** The preview plans from catalog ownership instead of walking the filesystem repeatedly, lookups are batched, selected titles are locked for the job, and progress/outcome reporting matches other long-running operations.
- Rename application refuses to overwrite an existing destination and isolates a failure to the affected file. Cross-device and network-share moves preserve configured or source permissions, normalize Unicode path identity, retry stale post-copy size reads, stage data under a sibling partial name, and promote it exclusively so scanners never observe an empty final media file.
- Automatic generated-component clipping is Windows-only, where the UTF-8-safe budget and filename-extension preservation remain in place. Unix and macOS pass the complete sanitized component to the filesystem. Explicit template truncation filters are unchanged.
- Absolute-number-only anime imports now fill `{episode}` from the resolved season-relative episode metadata, preventing names such as `S01E`. Season-folder templates also accept escaped literal braces.

## Upgrade Notes

- **Update torrent download-client plugins before or with this release.** Scryer checks removal and file-move verdicts against the plugin version that first reported them accurately. Torrents on an older plugin are held rather than removed, and their imports hardlink or copy instead of moving data, until the plugin is updated in Settings > Plugins.
- **Goal-met and failed torrent removals now delete the download client's copy of the data**, matching Sonarr. When the seeding gate releases a verified import, the entry and client payload go together. Failed cleanup deletes data only when the client says removal is safe. Library hardlinks are unaffected; blackhole, ignored, and usenet items never receive this torrent-specific delete request. Cross-seeded payloads carry the same caveat as in Sonarr.
- **Prowlarr minimum seeders affect admission, not seed-goal selection.** A Prowlarr minimum governs seeder admission while ratio and time goals continue through their independent resolution chain. Prowlarr goals without an imported minimum use the global profile/default minimum. If you raised Scryer's floor for Prowlarr-managed indexers, set the value in Prowlarr's app profile or assign a Scryer profile directly to the indexer.
- Delayed releases persist their observed seeder count and are re-judged against the current threshold on automatic promotion. Older pending rows have an unknown count and remain eligible. Automatic reacquisition after a failure goes through the same admission check.
- **`Remove failed` defaults to on.** The startup migration changes saved `false` routing values to `true` because 0.18.16 persisted `false` as its normalized default. If you intentionally disabled failed-download cleanup on an existing route, turn it off again after upgrading.
- **Burned usenet imports delete client data only when that route's `Remove failed` toggle is on.** Scryer protects library roots, title folders, recycle bins, and remote-mapping roots while removing job output, and asks SABnzbd and Weaver to delete their held data where supported. Burned torrents still wait for the seeding gate before removal.
- **Scores are re-baselined.** Existing quality-profile minimum-score values are reset to unset because the old values included tier points. Set a new floor against the new scale if needed. The cross-tier minimum-delta setting is deprecated and ignored because tier is now compared before score.
- Database migrations add seeding profiles and frozen submission goals, login-factor challenges and required password replacement, pending-release seeder observations and standby data, submitted and announced size tracking, and the title-credits cache. `wanted_items.current_score` is removed because current score is always derived.

### GraphQL API compatibility

- This release removes no GraphQL fields, types, or enum values. It does add enum values and optional input fields, which the schema checker classifies as dangerous because generated clients and exhaustive enum handling may need to be regenerated or updated.
- Enum additions: `DomainEventTypeValue.SEEDING_STARTED`, `DomainEventTypeValue.SEEDING_COMPLETED`, `DownloadActivityFilterValue.WARNING`, `DownloadDisplayStateValue.WARNING`, `DownloadQueueStateValue.WARNING`, `JobKeyValue.TITLE_RENAME`, `TitleHistoryEventTypeValue.SEEDING_STARTED`, `TitleHistoryEventTypeValue.SEEDING_COMPLETED`, and `TrackedDownloadStateValue.IMPORTED_SEEDING`.
- Optional input additions: `DownloadClientRoutingEntryInput.seedingProfileId`; `LibrarySettingsInput.metadataLanguage` and `LibrarySettingsInput.useSeasonFolders`; `MediaRenamePreviewInput.renamableOnly` and `MediaRenamePreviewInput.maxItems`; `QualityProfileCriteriaInput.cutoffScore`; `QueueDownloadInput.sizeBytes`; `TitleOptionsInput.metadataLanguage`; `UpdateMediaSettingsInput.useSeasonFolders`; and `UpdateSecuritySettingsInput.mfaRequireJellyfinLogin` and `UpdateSecuritySettingsInput.mfaRequireEmbyLogin`.

## Other Improvements

- The indexer and seeding-profile tables show Prowlarr's effective minimum-seeders value and call out thresholds that differ from the default, including an explicit disabled check.
- Seed-time fields accept durations such as `90m`, `36h`, `1d 12h`, or `2w`; a plain number still means minutes.
- Settings > Indexers uses a dedicated side rail for indexers, seeding profiles, and related panes. Help text distinguishes the global admission floor from routing-only profile assignments.
- Torrent queue rows show their seeding state, observed ratio and seed time, and the goals being measured. Activity history's *Download ignored* filter now matches the corresponding event correctly.
- Startup serves the application without waiting for full title-metadata hydration, and opening a series hydrates only the seasons expanded by the operator.
